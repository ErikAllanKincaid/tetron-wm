Themes · colors · one small TOML file

Make your own tetron-wm theme

A theme is a short list of named colors. Every color on the desktop comes from one key, so once you know which key paints which part of the screen you can restyle the whole thing, share it, and have it behave on a 16-color console too. This guide shows the keys on a picture of the desktop, then walks you through building a theme of your own.

What a theme is, and why it is only colors

A theme file holds colors and nothing else. Layout, the position of buttons, and the readability rules stay in the program. That is on purpose: a theme can look odd, but it can not move a close button off the title bar or hide the text it draws. The worst a bad theme can do is look ugly, and the program warns you in the debug log when a pair of colors is hard to read (it never refuses to load one).

Colors are named by role, not by place. accent is not "the blue thing"; it is the color of highlighted labels and the fill of the "+" button. One role can be used in several places, and the next section shows where.

Everything is optional. A theme names a base (one of the built-ins) and only lists what is different. Three lines are a valid theme.

    01Start from a theme you like

    Do not start from a blank file. Writing out the whole list is slower and easier to get wrong than changing a few lines of a working theme. You have two ways in.

    Inherit. Name a base and list only what changes. Unlisted keys come from the base, so this is the fastest way to a result.

    Copy. Dump a built-in to a file you own, then edit it. The file is named after the built-in, so rename it before you change it, otherwise it replaces the built-in of that name.

    The dumped file lists every key, including the optional ones (with the values they were derived to), and shows the [ansi] and [vt16] tables commented out, ready to switch on.

    02Try it, and see it change

    Switch to it by name, or pick it in Settings → Appearance. The themes folder is checked once a second, so a new file is found without a restart.

    After you edit a file

    The theme that is in use keeps the colors it loaded. Run tetron-wm theme ember again (or pick it again in Settings) and the edited file is read. That makes a quick loop: edit, save, run the command, look.

    Change one key at a time. When something looks wrong, the picture above tells you which key it was.

    03Keep text readable

    Most unreadable themes come from a handful of pairs. tetron-wm checks them when it loads your file and writes a line to ~/tetron-wm-debug.log (also in the in-app Logs viewer) for each that is too close. The number is a contrast ratio, where 1 means identical colors and 21 means black on white. See WCAG contrast for the idea behind it.

    PairMinimumWhy
    text on window_bg3.0Everything you read and every terminal.
    text on desktop_bg2.5Icon labels when there is no scrim.
    window_bg on accent2.0Text on affirmative buttons.
    window_bg on close_fg2.0Text on destructive buttons.
    title_blur vs desktop_bg1.12An inactive title bar the same color as the desktop disappears.

    These are minimums for the program to stay quiet, not targets. For low vision, aim for 7 or more on text and window_bg, as the built-in contrast theme does. Other pairs are not checked, so look at accent on active_bg (the selected row) and title_fg on both title bars yourself.

    04Give it a picture

    A theme can bring a wallpaper. Put an image next to the theme file with the same name and it is shown while the config key wallpaper is default: ember.toml plus ember.jpg (also png and webp). To use a different file, or none, set the theme's own key.

    Pictures are drawn as colored text cells with chafa. Without it, black, a hex color and none still work. A picture you chose yourself in Settings stays when the theme changes. On the 16-color console a picture turns to noise, so default shows desktop_bg there instead.

    05The colors apps see: [ansi]

    Programs inside your windows do not know your theme. When ls --color prints a directory in blue, it only asks the terminal for "ANSI color 4" and the terminal decides what blue is. The [ansi] table is that decision: the 16 colors a program can ask for by number, row 13 on the picture.

    Why you would change it: the default palette suits a dark window. On a light theme the default yellow and white are close to invisible on a white window, and a theme with a strong palette (a favorite editor scheme) looks wrong if apps keep different reds and greens. Set any subset; the rest keep the default.

    The names are black red green yellow blue magenta cyan white and the same eight with a bright_ prefix, in that order (palette 0 to 15). Apps that ask the terminal for a color with a query (OSC 4) get your values too, and apps that are already running repaint when you switch themes. Programs that print their own 24-bit colors are not affected, and the 256-color cube is not part of the table.

    06The 16-color console: [vt16]

    On a bare Linux console (and with TETRON_WM_COLORS=16) the screen has only 16 colors, and only 8 of them can be a background. A subtle dark blue selection and a dark grey window both round to black, and the selection vanishes. So below 256 colors tetron-wm does not round your colors. It picks a 16-color palette entry for each role instead, so the roles that must stay distinct (desktop, window, selection, focused title) do.

    It picks by looking at the hue of your color: a teal desktop becomes cyan, a navy title bar becomes blue. A color with no clear hue (a grey, black or white) carries no hint, so it takes a generic default, and for the selection that default is teal. If your theme uses greys, that is the surprise to expect, and [vt16] is the fix: give the role a palette index yourself.

    IndexColorIndexColor
    0black8dark grey (foreground only)
    1red9bright red
    2green10bright green
    3brown11yellow
    4blue12bright blue
    5magenta13bright magenta
    6cyan14bright cyan
    7light grey15white

    Indices 8 to 15 are for text colors. Roles that are backgrounds (desktop_bg window_bg title_focus title_blur menubar_bg dock_bg active_bg) can only use 0 to 7; a bigger number is folded back into that range. The roles you can set are all the color keys except shadow.

    Leave [vt16] out until you have looked at your theme on the console. For themes with real hues the derived result is usually right. To see it on a normal terminal, start with TETRON_WM_COLORS=16 tetron-wm. Whatever you pick, text on a background is still checked for legibility at draw time, so a pair that would be unreadable is flipped to black or white.

    When something looks wrong

    SymptomFix
    My edit does nothingRun tetron-wm theme NAME again. The theme in use keeps its loaded colors until it is selected.
    The theme is not in the listThe file must end in .toml and sit in ~/.config/tetron-wm/themes/ (or the folder set by theme_dir). A file that fails to parse is skipped; the reason is in ~/tetron-wm-debug.log.
    One color did not changeAn invalid value keeps the inherited color. Check the log for invalid color. Quote the value: "#ff9e64".
    My new file replaced a built-inA file named like a built-in (midnight, gruvbox, pastoral, windows) overrides it. Rename the file.
    Selection is invisibleactive_bg is too close to window_bg. Move it further, or give it a different hue.
    Selection is teal on the consoleYour active_bg is a grey. Set [vt16] active_bg (see 06).
    Green and red status text is hard to readSet success and error; the derived ones assume a plain light or dark window.
    Text on the "+" button is lostSet accent_fg to a color that contrasts with accent.
    Apps still draw the old colorsApps already running repaint on a theme switch only when the app server is protocol 6 or newer (Settings → About). Restart the app server, or start the app again.
    Everything is grey, no color at allThe terminal is in black and white mode (NO_COLOR or TETRON_WM_COLORS=mono). Only how light or dark each role is matters there; hues are dropped.

    Share it

    A theme is one file, plus an optional picture with the same name. Send ember.toml (and ember.jpg) and the other person drops them into their themes folder. Nothing in the file is specific to your machine. A theme does not change layout, so it behaves the same on every screen size and over SSH.

    The extra themes that come with the suite installer (nord, dracula, dawn, newmoon, contrast) are ordinary theme files, so they make good worked examples. Read them with cat ~/.config/tetron-wm/themes/contrast.toml.

    Built so the next person can understand it, adapt it, and pass it on.
