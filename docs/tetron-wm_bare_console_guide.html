Linux console · KMS/DRM · no display server

A mouse-driven desktop on a bare text console

tetron-wm gives you floating windows, a taskbar, and a real pointer on a Linux machine with no X11 and no Wayland. This walks through why each piece is there, not just the commands, so you can build it, adapt it, and explain it to someone else.

The problem: the kernel console is a bad terminal

When a Linux box boots without a graphical server, you land on a kernel virtual terminal (VT) — the thing you reach with Ctrl+Alt+F2. It works, but it is a terminal from another era: a fixed bitmap font, 16 colors, and no mouse. A desktop like tetron-wm needs the opposite of all three: 24-bit color for themes and wallpaper, a scalable font with box and block glyphs for its window chrome, and a pointer that both the desktop and the apps inside it can read.

You could start X or Wayland just to host one terminal, but that drags in a display server, a compositor, and GPU drivers you did not want on a headless or minimal box. There is a lighter layer that sits exactly where the kernel VT sits and speaks all three languages: kmscon.

The stack: who does what

kmscon is a userspace console that draws straight onto the framebuffer through the kernel's KMS/DRM interface. It replaces the kernel VT as the thing you log in to, and it provides truecolor, fontconfig fonts, XKB keyboard layouts, and mouse-report passthrough. tetron-wm then runs inside kmscon as an ordinary full-screen program. No display server is involved at any layer.

Over SSH none of this applies: your SSH client is the terminal, so tetron-wm just runs in it directly. kmscon is only for sitting down at the physical machine.

Why a specific kmscon, not the one in your package manager

Truecolor landed in kmscon 9.0, and mouse-report passthrough lives in the actively maintained fork by Aetf (Aetf/kmscon + Aetf/libtsm). The stock kmscon that older distributions still ship predates the mouse support, so the pointer will not work. That one detail is the whole reason the install is not a one-liner on every distro.

Debian trixie

The maintained line is already packaged in trixie-backports (numbered kmscon 10 / libtsm4 4.7.1 there). A clean apt install, no compiler.

Ubuntu / Mint

apt only has the too-old pair, so you build the fork from source: libtsm first, then kmscon. Two small meson projects.

Good to know

kmscon has no --version flag. Do not go looking for one. The Debian package numbers (10 / 4.7.1) and the upstream tags (9.x / 4.x) are the same code counted differently, so do not gate anything on "version ≥ 10".

The trick that makes a wallpaper possible on text

A text console has no pixels to paint a photo with. So how does tetron-wm show an image wallpaper? It does not draw pixels at all. It runs chafa, which turns any JPEG or PNG into truecolor cell-art: each character cell is filled with a block or half-block glyph in a foreground and background color chosen to approximate that patch of the image. With 24-bit color and a few thousand cells, the result reads as a photo from normal viewing distance. The same technique is why the wallpaper works identically on kmscon, in a GUI terminal, and over SSH. Install chafa and drop in an image; no chafa just means a solid-color desktop, with everything else intact.

Why those two flags

-Dc_args=-Wno-error: the tagged release builds with -Werror, and a newer GCC trips a format-truncation warning that is harmless here. -Dtests=false: the test subdir needs libcheck you do not have. A source build lands kmscon at /usr/local/bin/kmscon — remember that path for step 06.

When something looks wrong

SymptomFix
Solid-color desktop, no wallpaperchafa is missing — do step 02.
Colors look flat / 256-ish on kmsconSet truecolor = true in config.toml.
No mouse on a raw VT (no kmscon)apt-get install -y gpm && systemctl enable --now gpm. Not needed under kmscon, which passes the mouse itself.
Boxes/tofu with icon_style = "nerd"Install a Symbols Nerd Font and run fc-cache -f, or stay on ascii.
Wallpaper shows glyph tofu on kmsconThe console font lacks the sextant glyphs chafa uses — a font-coverage gap, not a bug. The DejaVu/Terminus fonts from step 03 help.
tty1 login is brokenFrom another VT or SSH: systemctl disable --now kmsconvt@tty1 && systemctl enable --now getty@tty1.
Debug the desktop itselfRead ~/tetron-wm-debug.log, or open the in-app Logs viewer.

Optional extras

  • A Nerd Font — only if you want icon_style = "nerd". Install the tiny "Symbols Only" font from ryanoasis/nerd-fonts into ~/.local/share/fonts and run fc-cache -f. The default ascii needs no font.
  • gpm — a mouse on a raw VT without kmscon. Under kmscon you do not need it.
  • tetron & tetron-tui — the mesh-VPN daemon and its dashboard. They power only the optional tetron tray segment; the desktop runs fine without them. Add them only if you use that VPN.
The shortcut, once you understand it

The tetron-wm repo ships install.sh (binary + chafa + Nerd Font) and scripts/install-kmscon.sh (the backports-or-source logic from step 03, automated). Now that you know what they do, running them is a choice, not a leap of faith.
